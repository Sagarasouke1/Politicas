# 🛡️ GOBIERNO DE SEGURIDAD DE INFRAESTRUCTURA TI

## 1. Objetivo

Definir el marco de gobierno para el control, supervisión y cumplimiento de accesos a servidores Linux SCP y Windows ANALÍTICA.

---

## 2. Principios de gobierno

- Seguridad por diseño.
- Mínimo privilegio.
- Trazabilidad completa.
- Separación de funciones.
- Responsabilidad individual.
- Continuidad operativa controlada.

---

## 3. Responsabilidades

| Rol | Responsabilidad |
|---|---|
| Administrador de Sistemas | Administrar accesos, aplicar controles y conservar evidencia |
| Jefatura TIC | Solicitar accesos conforme al proceso y respetar controles |
| Coordinación Infraestructura | Solicitar accesos limitados y documentados |
| Soporte TI | Atender actividades autorizadas únicamente |
| Auditoría / Revisión Interna | Validar cumplimiento y evidencias |

---

## 4. Reglas de cumplimiento

- Ningún acceso será otorgado por jerarquía.
- Todo acceso deberá estar justificado.
- Todo acceso deberá estar autorizado.
- Todo acceso deberá ser registrado.
- Todo acceso temporal deberá caducar.
- Todo acceso fuera de flujo será considerado no autorizado.

---

## 5. Continuidad operativa

La continuidad operativa no elimina controles de seguridad.

Cualquier acceso bajo este argumento deberá cumplir con:

- Incidente documentado.
- Solicitud formal.
- Aprobación.
- Vigencia temporal.
- Registro de actividad.
- Revisión posterior.

---

## 6. Evidencia requerida

- Ticket o solicitud.
- Aprobación.
- Registro de usuario.
- Log de acceso.
- Log de actividad.
- Evidencia de revocación.

---

## 7. Revisión periódica

La matriz de accesos deberá revisarse de forma mensual o cuando exista:

- Cambio de personal.
- Cambio de rol.
- Incidente de seguridad.
- Cambio de infraestructura.
- Solicitud de auditoría.

---

## 8. Incumplimiento

El incumplimiento de este marco podrá ser considerado una violación de seguridad y deberá ser escalado conforme a los procedimientos internos.
